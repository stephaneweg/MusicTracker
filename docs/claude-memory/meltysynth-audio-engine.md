**Objectif** (2026-07-22) : porter le rendu audio sur le `Synthesizer` officiel de MeltySynth pour un playback SF2 fidèle (layering multi-samples + enveloppes DAHDSR + loop modes + filtre/LFO), et à terme supprimer l'instrument editor + les `WaveFunction` du synthé maison ([[procedural-instrument-synthesis]]).

**Pourquoi** : le synthé maison ([[sequencer-photoshop-layers]]) ne joue qu'UN sample par note (`AudioPatch.GetPart`) → sur les presets à couches attaque+tenue (ex. Cello de MuseScore : instruments `Cello_F/M/P` séparés par vélocité + `Clo Attack` one-shot), il choisissait parfois le sample d'attaque one-shot par root le plus proche → note coupée net après ~0,2 s (bug D3/C#3 confirmé par simulation). Fix intermédiaire posé : pénaliser les one-shot dans `GetPart` (préférer le sample bouclé). Vrai fix = vrai synthé SF2.

**Contraintes découvertes** :
- **NuGet MeltySynth impossible en net48** : toutes les versions ciblent netcoreapp3.1/netstandard2.1. → on vendorise la source officielle (repo https://github.com/sinshu/meltysynth, MIT), down-levelée net48.
- Le MeltySynth vendored d'origine était amputé (parseur seul, samples en `float`/24-bit, `WaveDataArray` float).

**ÉTAPE 1 FAITE (build vert, aucune régression)** : remplacé tout le dossier `MeltySynth/` par la source officielle (parseur + `Synthesizer` complet). Down-leveling net48 = : `MathFShim.cs` (net48 sans System.MathF : Abs/Sqrt/Sin/Cos/Pow/Log/Log10/PI + Clamp ; sed `Math.Clamp`→`MathF.Clamp`) ; `SoundFontSampleData` I/O Span→`ReadBytes`+`Buffer.BlockCopy` (+ check OggS via bytes) ; `Zone.cs` `ArraySegment.Empty`→`new ArraySegment(Array.Empty)` ; `Synthesizer.cs` `Dictionary.TryAdd`→ContainsKey/Add ; csproj `<LangVersion>9.0</LangVersion>`+`<Nullable>annotations</Nullable>`. `SoundFont.WaveDataArray` rendu **public** (short[]). `AudioPatch` adapté : wave buffer désormais `short[]` normalisé ×(1/32768) dans `ResampleSegment`/`CatmullRom` (const `SampleNorm`). MeltySynth n'est référencé QUE par AudioPatch.cs ; tout le reste passe par `InstrumentCatalog`/`AudioPatch.patchList` + graphe WaveFunction (INCHANGÉ, ancien rendu tourne encore).

**Modèle de layering confirmé (probe)** : preset Cello = 9 zones (P vel0-79, M 80-102, F 103-127 tenus + 6 zones `Clo Attack` splittées par vélocité). Pour MIDI 50 vel127 : `Cello-D#2` (modes=Continuous, atk0.05s rel0.6s) + `CelloAttack-D2` (modes=NoLoop one-shot, decay0.7s). FluidSynth/MuseScore jouent TOUTES les zones couvrantes en parallèle (voix indépendantes, chacune sa DAHDSR) et somment ; ils ne « choisissent » pas.

**CANAUX ILLIMITÉS FAIT** : `channelCount` (Synthesizer) passé de const statique 16 → champ d'instance lu depuis `SynthesizerSettings.ChannelCount` (nouveau knob, défaut 16, borne 16..1024). L'app dimensionne UN synth = nbPistes+1 → pistes illimitées sans pool (au-delà de 1024 = pool). Coût nul (un canal = petit objet Channel ; voix mutualisées par MaximumPolyphony, pas de boucle par canal au rendu). Perc = canal 9 unique (plusieurs batteries le partagent).

**TROU PIANO vél 80-107 — VRAIE CAUSE TROUVÉE & RÉSOLUE (2026-07-23)** — SUPERSÈDE les diagnostics « annulation de couches / cause inconnue / non-corrigeable » ci-dessus (l.26, 33, 35). Investigation alignée sur FluidSynth/MuseScore (source). DEUX bugs réels dans notre port de modulateurs :
1. **Sommation de modulateurs dupliqués** (`InstrumentRegion.CombineModulators` concaténait global+local sans dé-dup, `RegionPair.NoteOnAttenuationFromModulators` sommait tout). Or SF2 2.04 §9.5.1 : un modulateur local d'identité (source+dest+amtSrc+transform) identique à un global le **REMPLACE** (pas additif). Les pianos MuseScore_General portent le modulateur vél→InitialAttenuation en double (global 800 + local 700 cB) → on sommait 1500 au lieu de 700 → piano ~19 dB trop faible, courbe non-monotone. Le violoncelle n'a qu'un seul → intact (d'où l'asymétrie). FIX = `CombineModulators` applique l'override (local remplace le global identique).
2. **Modulateurs de FILTRE jamais appliqués** (on n'appliquait les modulateurs QU'à InitialAttenuation). Le vrai trou : les couches vél 80-107 ont un `ModEnvToFilterCutoff` BAKÉ à −2350 cents ; le SF porte un modulateur `vélocité→ModEnvToFilterCutoff = +6500 (linéaire)` censé le compenser (frappe forte = plus brillant). Sans lui, le passe-bas se ferme à ~77 Hz et MUTE la note (vérifié : à vél 90 une voix ISOLÉE = −52 dB alors que gain 0.0935 > vél 60 ; `dynamicCutoff=True modEnvToCutoff=−2350`). FIX = généralisé `Modulator.NoteOnContribution(dest,…)` + `RegionPair.InitialFilterCutoffFrequencyModulated/ModulationEnvelopeToFilterCutoffFrequencyModulated` appliqués dans `Voice.Start` (gen8 + gen11). Skip les modulateurs à amount-source (liés). Ajouté `MathFShim.Round`.
