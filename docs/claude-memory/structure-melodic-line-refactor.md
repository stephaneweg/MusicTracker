Planned direction (2026-07-13), GATED on the user ear-validating the hand-built `ghibli_valse.sq` proof-of-concept (Desktop) that already does this manually.

Idea: make `Orchestrateur` (the "🏛️ Créer structure…" feature, `btnCreateStructure_Click`) emit a **`MelodicLineModule`** (rhythm skeleton only) for **intro + melody + counter-melody** instead of `PlayRiffModule` riffs. The `MelodicLineEngine.GenerateLine` + `Harmony.ChordAt` (structure mode reads the arrangement grid) then derive the pitches at render time — "as if composed without a structure". This DELETES the melody-pitch machinery in `Orchestrateur.RenderSection` (theme reconstruction → fold-on-rhythm → transpose → voice-lead → FitRange) and the per-section `MelodyRiffId`/`CounterRiffId` relinking. Counter-melody = **voice 1** of the same MelodicLine (VoiceCount=2, same staff) — matches the user's polyphony intent. Accompaniment/nappe/bass stay as `PatternGeneratorModule`.

The generator then only needs a **coherent rhythmic motif per section**. The "style" (family × mood × meter) drives 3 things: (1) harmony choice [already], (2) chord articulation motif, (3) melodic-line rhythm motif — all pulled from a **catalogue**: JSON keyed `style × humeur × métrique → { chord-articulation grids, melodic-line rhythm grids }`, structurally like the existing [[theme-library-seed-engine]] (`Data\themes\*.json` + `index.json`) and the generator style tables [[generators-and-cadence]]. Extend family by family.

Validated feasibility: `ghibli_valse.sq` (C major 3/4 waltz, 64 bars, 8 units Intro/Theme/4×Dev/Reexpo/Outro) = hand-built .sq with exactly this shape — MelodicLine track (2 voices at climax) + custom per-section chord articulation + open-voiced nappe + arrangement chord grid. The melody the engine derived is musical (stepwise, chord-locked, borrowed-chord color at the climax). Generator script: scratchpad/gen_ghibli.py.

Decisions (user, 2026-07-13): bass = dedicated low melodic-line track; dev varies rhythm+harmony+register/voice; counter = TOGGLE same-staff(voice1)/two-staff; migrate FULLY; dedicated catalogue; rework dialog.
