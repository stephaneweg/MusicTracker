The agreed plan to replace the random-sounding Markov melody (see [[generator-style-fidelity]] USER VERDICT): a **curated theme library** (LLM/hand-authored quality motifs) **seeds** the existing structure/variation/harmony engine, which then develops the seed deterministically. This is the hybrid "LLM = motif factory (offline), runtime = 100% procedural" approach. 3 steps the user signed off (2026-06-19): (1) author a series of themes per composer family + style; (2) reuse the EXISTING form/variation/harmony machinery (it already exists, ~90%); (3) wire together; extending = "just feed the JSON file".

**Key discovery:** step 2 was already built. `ArrangementEngine.ApplyVariation` (VaryRhythm/RefitThemeModal/MotoPerpetuo/Retrograde/InvertContour/BorrowMode/Ornament/BuildVariations), `FormSpec`/`Forms` (per-composer form templates), `MusicTheory.Cadence` (30 styles) + `VoiceLead`, `ComposedArrangement` (Theme/Chords/Motifs/BassMotifs). The ONLY missing link was a good seed theme — the seed came from the drifting Markov `GetNote`.

**The single graft point** (Phase 1 DONE, builds, logic-verified headless): `Orchestrateur.Compose` builds the whole piece from two locals — `themeA` (= `gen.GetNote(...)`) and `themeAChords` (= `gen.GetChords(...)`); every section transposes/varies/refits them. So replacing just those two with a curated motif leaves form/key-plan/variation/accompaniment untouched. Two edits in `Orchestrateur.cs`: (a) compute `gen`/`style`/`libEntry` BEFORE `Forms.ApplySizes` and pass the library's `ThemeBars` so the theme section is sized to the curated theme; (b) after `themeA` is computed, if `libEntry` matches, `themeA = ParseMelody(...)` transposed by `delta=(tonicPc - libKey)`, `themeAChords = Fit(libEntry.HomeChords(delta))`. Fully backward-compatible: no match → original Markov behaviour.

**Files:** `MusicTracker/Engine/Timeline/ThemeLibrary.cs` (NEW — model + `Load()` (no cache, reads each compose) + `Find(family,style,minor)` + `ParseMelody(tokens,spq)` + `DurToSlices` + `TransposeNotes` + `ThemeEntry.HomeChords(delta)` + `MotifSpec.ToChordMotif()`). JSON at `MusicTracker/Data/themes/theme_library.json` (csproj copies `Data\themes\*.json` PreserveNewest; resolved via `AppPaths.Local`). `BaseComposerV3.FamilyKey` virtual ("generic") overridden: Ghibli→"ghibli", Vivaldi→"vivaldi", Bach & BachClavier→"bach". csproj: `<Compile Include="Engine\Timeline\ThemeLibrary.cs" />`.

**JSON contract (token melody format = the .mscx scripts):** `themes[]` each = {composer, style (must match a composer Styles string), name, key{tonicPc,minor}, tempo, spq, themeBars, melody ("`<midi[+midi]>/<dur>`" tokens, '|'=bar sep, 'r'=rest, dur 1/2/4/8/16/32 + '.'dotted/'t'triplet — MUSICAL durations so spq is the engine resolution; app Note = MIDI−12), harmony{cadenceStyle (−1=use chords), chords[{root(pc),q(PatternGenerator quality idx)}]}, form (advisory), accomp/bass (MotifSpec, degree-based), variations[] (ApplyVariation tech order)}. First entry: Ghibli/Berceuse = the `ghibli_lullaby` theme (8 bars, descending-bass C-G-Am7-G-F-C-Dm7-G7).

**Wired now (Phase 1):** melody + chord-grid seeding for non-`GeneratesOwnMelody` composers (Ghibli/Bach/generic). **NOT yet wired (Phase 2 / TODO):** accomp/bass `MotifSpec`→`arr.Motifs`/`BassMotifs` (initial compose uses `gen.MakeBacking`, not `arr.Motifs` — only the edit/regen path reads `arr.Motifs`); `harmony.cadenceStyle` generation (only explicit `chords` honoured); `GeneratesOwnMelody` styles (Vivaldi) ignore the seed (their melody is per-section figuration, not themeA).
