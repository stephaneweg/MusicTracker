**JSON contract** (`Engine/AI/AiArrangement.cs` DTOs + `AiArrangement.Parse` strips ```fences): `meter{num,den}`, `key{tonic,mode}`, `bpm`, `sections[{name,measures}]`, `chords[{measure,degree(1..7 RELATIVE to key),quality}]`, `articulation[{section, motif[{voice(0..10 grid row),start,length in temps}] OR style}]`, `melodicLines[{section,track(role),instrument?,fromMeasure,measures,durations[temps],anchor,contour,register,voice}]`. The model ALSO chooses key/meter/**bpm**. `AiArrangementPrompt.SystemPrompt` embeds the live enum lists + the custom-motif voice-row legend (0=bass,1=root,2=3rd,3=5th,4=7th,5=root+8,6=9th,7=3rd+8,8=5th+8,9=7th+8,10=9th+8); `UserPrompt(style, measures, intention)` — the dialog has an "Intention musicale" free-text box (e.g. « musique sombre », « rappelle l'enfance »).

**Translation** (`AiTranslate`, pure): name→index matching (exact→leading-word→contains) for quality/style/contour/anchor; `RootPc(key,degree)` = TonicPc + `MusicalMode.Scale(Effective(key))[deg-1]`; `ParseKey`; `BuildRhythmNotes(durations,totalSlices,spq=4)` tiles the motif into voice-row-0 RiffNotes.

**DEVELOP-THEME mode (2026-07-18):** right-click a riff box → **"🤖 Varier le thème avec l'IA…"** (`VaryThemeWithAi`). `BuildThemeContext` = compact text of the selected riff's notes (`pitchMIDI@startTemps x lenTemps`) + the chords under it (from ChordTrack, degree+quality) + key/meter. Passed as `AiComposeDialog.ThemeContext` → `AiArrangementPrompt.UserPrompt(...,theme)` reframes as "DÉVELOPPE/VARIE ce thème" (AI chooses the development's chords, keeps key/meter). Applied via `ApplyAiArrangement(a, fixNotes, append:true)`: append mode SKIPS the replace-confirm + meter/key/bpm reset + Tracks.Clear; computes `baseBeats` = current timeline end rounded up to a bar; shifts chords (first new chord gets a leading gap) and riffs/melodic (via `GetOrCreateInstrTrack` reusing same-name tracks + `TrackEndBeats` cursor) to start after existing content. Harmony-fix + note-abs-detect use the DEV-RELATIVE beat, placement uses the absolute beat.

**Placement** (`ApplyAiArrangement`): sets project.TimeSig+Key (+`SyncKeyToolbar`), BPM→`project.Tempo[0].Bpm`+txtBpm (NOT `project.Bpm` — that field isn't on TimelineProject), `barTemps=RulerBeatsPerBar()`. Melodic lines → grouped by `track` role, one `TimelineTrack` (Instrument) each; each part = a `MelodicLineModule` (BeatsPerBar=measures×barTemps, Contour/Anchor/RegisterShift set, SilenceBefore = gap to fromMeasure). `EnsureChordTrack` re-pins Accords at bottom.

**Riff start GOTCHA (2026-07-18):** models (esp. Gemini) sometimes give riff note `start` as ABSOLUTE temps from the PIECE start, not relative to the riff → double-offset (SilenceBefore + absolute start) + notes past the riff length dropped → "only the first section shows". Fix: `BuildRiffNotes(..., startOffsetTemps)` subtracts an offset; `ApplyAiArrangement` detects absolute (min note start ≥ `(fromMeasure-1)*barTemps`) and passes that as the offset. Prompt also clarifies start is relative to the riff. Handles both absolute and relative.

**Parse robustness (2026-07-18):** Mistral returns `anchor`/`contour` (and sometimes `quality`/`style`) as NUMBERS not strings → STJ "value could not be converted to string". Fix: `FlexibleStringConverter : JsonConverter<string>` (reads Number/Bool tokens as string) on those fields + `NumberHandling=AllowReadingFromString` on the options + `IndexOrMatch` (a numeric string → direct clamped index) in ContourIndex/AnchorIndex/StyleIndex. **MODEL'S OWN LAYERED REASONING (gemini, shared by user 2026-07-20):** for African/polyrhythmic music it describes a top-down-but-ITERATIVE build in layers — (1) Terrain: key+tempo, (2) Climat: rich chords (m(add9), #11), (3) Moteur: the rhythmic articulation groove, (4) Parole: lead + contrechant crossing without stepping on each other — AND it notes the CAUSAL ORDER can INVERT by style: in African/polyrhythmic music the melody & drum groove DICTATE the harmony, not the reverse. DESIGN IMPLICATION: the schema deliberately does NOT force a chord-first order — it just requires all parts present + coherent — which is exactly what lets the model apply the right per-style causality (harmony-from-groove for polyrhythmic, harmony-first for tonal). So do NOT over-constrain the reasoning ORDER in the prompt; keep constraining the FORMAT + the parts required. (Also: the model has internalized the 'contrechant complementary to the lead' rule as a principle, not just a one-off instruction.) **User reports BETTER results than NotaGen, in BOTH riff mode (full freedom) and melodic-line mode** → the winning approach = LLM decides musical STRUCTURE, the app engine renders (in-scale pitches, voicing, articulation). **CORE PROJECT PRINCIPLE (user, 2026-07-19): "structure the piece in CHORDS first (by degree), with FREEDOM on the motif" was THE necessary lever** — reached the target quality, beating end-to-end NotaGen.
