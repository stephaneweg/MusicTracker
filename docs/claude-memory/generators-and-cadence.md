Chord (`PatternGenerator`) and drum (`DrumPattern`) generators each have a `StyleNames[]` table and `CustomStyle = StyleNames.Length - 1`.

- **Generator thinks in NOTES + durations** (2026-06-15 refactor): `PatternGenerator.Generate` (built-in styles) and `GenerateCadence` now emit the canonical `RiffNote` list DIRECTLY (clean intended durations, no détaché slice-gap), set via `Riff.Notes`/`LengthSlices` (NOT `.Slices`). Patterns live in `BuildVoiceEvents(style, beats, voiceCount)` → `List<VoiceEvent{Voice,Start,Len}>` with CLEAN lengths (a held bar = 96 slices = ronde; Charleston = 36+12 = noire-pointée+croche; shuffle = 16+8 = triolet 2/3+1/3). Re-articulation of adjacent same-pitch notes needs NO gap: they're separate `RiffNote`s and `TimelinePlayer.ApplyTrackEvents` does release-then-attack at the same slice (`Retrig` → voice.Reset). So audio re-attacks AND notation is clean by construction (the old `gap=Max(1,q/12)` détaché that produced double-dotted figures is GONE). `GenerateCadence` concatenates NOTES (offset by i×barSlices), never slices (would re-merge). `BuildVoiceBar` (slices, for the editor seed only) now just RASTERIZES `BuildVoiceEvents` with a 1-slice visual gap. The **"Personnalisé"** path stays slice-based (hand-drawn grid). NB: tango (15) is now an eighth stab, funk (17) clean 16ths, Charleston (6) a clean dotted-quarter+eighth cell (were messier/odd before). The `ScoreBuilder.PlaceLeaf` micro-gap absorption (≤ spq/12) is now a no-op for generated content but still cleans up live-recorded riffs.
- **Adding a style**: the "Personnalisé…" entry MUST stay LAST (CustomStyle is computed as Length-1). Insert new styles just BEFORE it, and add the matching `case` in `BuildVoiceEvents` (chords) / `RenderStyle` (drums). (2026-06-14: added chord styles 10–15 = arpège descendant, arpège croches, valse, reggae skank, marche, tango; drum styles 10–15 = marche, reggae one-drop, valse, punk, ballade cross-stick, trap.) (2026-06-15: added chord styles 16–21 = Bossa nova/Latin syncopé, Funk stabs-16e, Habanera/Tango basse, Ballade arpège tenu, Country basse alternée, Slow rock triolets 12-8; **22–25 = "Arpège : N croches + tenue"** (2/3/4 croches, and #25 = triolet) = an ARPEGGIO climbing the chord voices then a HELD note, via `ArpHeld(barSlices, vc, nNotes, noteDur, heldLen, heldChord)`. The held note's voicing is set by `HeldMode` (combo "Note tenue": 0=note seule, 1=accord plaqué, 2=fond+quinte, 3=fond+tierce), the CLIMB by `ClimbMode` (combo "Montée": 0=montant, 1=descendant, 2=Alberti via `AlbertiIdx`, 3=mixte — VOICE-LED, not a fixed alternation: the climb STARTS on the chord tone the cadence chose by voice-leading (`heldVoice`, nearest the previous chord) and runs up or down to avoid a wrap, so the order is free (starts low/mid/high per context) yet never random; standalone — no `heldVoice` — falls back to rotating montant/descendant/Alberti per cell via `PatternCellOffset` [transient = chord index, so the rotation varies across a cadence's chords]), and `HalveDurations` (bool, checkbox "Doubles-croches (÷2)" — halves every value). For a SINGLE held note (mode 0), the held chord-voice is VOICE-LED across a cadence: `CadenceChord.HeldVoice` = the chord tone closest to the previous chord's held note (computed in `MakeCadenceChords`, passed via `PatternGeneratorModule.HeldVoiceOverride` [JsonIgnore, transient] → `ArpHeld`; -1 = top, used for standalone chords). All these on BOTH modules, threaded into `BuildVoiceEvents(style, beats, vc, heldMode, climbMode, heldVoice, halve)` → `ArpHeld`. (`AlbertiIdx(i,vc)` shared with style #5.) Styles: 22 "2 croches+noire", 23 "3 croches+noire pointée", 24 "4 croches+blanche", 25 "triolet+noire", **26 "4 croches+noire" (3/4)**. **Alberti (#5) is now chord-aware**: root-5th-3rd-extension = 1-5-3-5 (triad) / 1-5-3-7 (seventh) / alternates 7th↔9th each group (ninth+), instead of the old lo-hi-mid-hi. All in `BuildVoiceEvents`, before Personnalisé. ALL articulation styles apply to BOTH the chord module and cadences (shared `BuildVoiceEvents`).)

- **Cadence generator** (`Engine/Flow/MusicTheory.cs` — replaced ChordProgression): `Cadence(key, startDegree, numChords, style, seed)` builds a progression from the chosen chord to the tonic in a named STYLE (`CadenceStyles`, 25: functional Auto/Authentique/Plagale/Jazz/Cycle-of-5ths/Demi/Rompue; pop Anatole/Pop/Doo-wop/EDM/Royal-road/Pachelbel; Blues + Blues mineur; modal/exotic Andalouse/Phrygien/Dorien/Mixolydien/Médiantes-chromatiques/Backdoor/Tritone-sub; "Morceau (auto)" which chains verse+chorus loops + a ii-V-I; **#23 Coltrane (Giant Steps)** = the three key centres a major third apart (0, ♭VI=+8, III=+4 augmented cycle), each via its own V7, non-tonic centres = Δ7; **#24 Forme AABA** = an A phrase (I-vi-ii-V) stated/repeated, a contrasting bridge B (IV-IV-V-V), then A, split into 4 equal sections of numChords). **#10/#25 = cycle of fifths in BOTH directions** (2026-06-15): #10 "↓ (desc.)" steps degree +3 (I-IV-vii-iii… roots Do-Fa-Si-Mi), #25 "↑ (mont.)" steps +4 (I-V-ii-vi… roots Do-Sol-Ré-La — what users expect). BOTH use **triads** (`Dt`/`Triad` maps 7th→triad: 6/8→maj, 7→min, 9→dim) since the cycle is classically triadic. `AutoRhythmStyle(10/25)` → **Alberti (5)** ("Do-Sol-Mi-Sol"). Functional styles = chosen-chord head-walk + tail; the rest = `(offset,quality)` templates tiled (offsets allow chromatic/borrowed ♭VII/♭VI/♭II/♭III). Everything ends on the tonic EXCEPT Demi (→V) and Rompue (→vi). `DegreeOf`/`TonicPc` are here too. Diatonic 7th chords (ii7/IVΔ7/V7/vi7/viiø7…) but the TONIC is ALWAYS a triad/6/add9 — NEVER a 7th (`MajorTonic`={0,11,13}, `MinorTonic`={1,12,14}). Random colour per seed: dominant V7/V9/V13. `numChords` = measures × chords-per-measure (the chord editor has both inputs + the style combo). Each cadence chord = `RulerBeatsPerBar()/cpm` beats.
- **Chord bass** (`PatternGeneratorModule.Bass` + `PatternGenerator.Generate`): a "Basse (fondamentale)" checkbox adds the chord ROOT one octave below — works with ANY built-in style. **2026-06-15: the bass is now ONE note per BEAT (held a quarter) shown as a SEPARATE VOICE** (2-voice notation). `PatternGenerator.Generate` emits the bass per the `BassPerBeat` flag: DEFAULT = ONE held note per MEASURE (a ronde); `BassPerBeat=true` = one note per beat. The bass PITCH is **adaptive** (2026-06-15): the ROOT placed at the closest octave ≤ the lowest played note (`chordLow - (chordLow-rootPc)%12`, drop an octave if it coincides), NOT a fixed octave below the root — so an inverted chord gets a small bass→chord gap, not a huge leap. (Side effect: when the gap is < 7 semitones — close inversions — `MarkBassVoice` keeps it in the chord voice rather than a separate stems-down voice; root position keeps the octave-below separate bass.) (UI: a "Basse" combo "Aucune / Par mesure (tenue) / Par temps" → sets `Bass`+`BassPerBeat`.) The SCORE separates it: `ScoreModel.MarkBassVoice(notes)` tags the lowest note at an onset `Voice=1` when it's ≥ 7 semitones below the next-lowest (the octave-ish gap of the added bass; safe — ordinary chords/monophonic riffs never trigger). `ScoreNote.Voice` (new field). `ClefByRange` ignores Voice==1 → a treble-range chord keeps the **clé de sol** even with a low bass. `ScoreView` splits `t.Notes` by Voice: voice-0 → normal `BuildSlots`/render; voice-1 → `BuildBassSlots` + `ComputeSpelling` + `DrawBassVoice` (heads + forced DOWNWARD stems, no beaming). So the chord keeps its rhythm and the bass is a steady stems-down voice underneath. (History: was a held whole-bar note that the single-voice score fused into the chord → everything became a ronde; then re-articulated per chord-onset; now a proper 2nd voice.)
- **Triadic tonic for triad styles** (2026-06-15): `Cadence` has a `triadic` flag (set for the cycle-of-fifths styles #10/#25, which use `Dt`). When set, the final tonic mapping keeps a plain triad instead of the random tonic COLOUR (triad/6/**add9**) — fixes "I asked for degree I (Do) but got a Ré in the chord" (add9 = the 9th). Non-triadic styles still get the colour.

- **Cadence = ONE `CadenceModule` brick** (2026-06-15, was N separate chord modules): `Engine/Flow/FlowModule.cs` adds `CadenceModule : FlowModule` (`[JsonDerivedType(..., "Cadence")]`) holding `List<CadenceChord>` (each = Root/Quality/Inversion/Degree) + shared `Octave`/`Style`(articulation)/`Bass`/`BeatsPerBar` + `CadenceStyle`/`StartDegree` (for re-roll). **Rendering helper** `PatternGenerator.GenerateCadence(CadenceModule)` builds each chord via a temp `PatternGeneratorModule` → `Generate` and CONCATENATES the bars into one `Riff` — so score/PDF/MIDI/MuseScore/audio all reuse the chord generator through this single riff. Wired into all four dispatch sites: `ModuleDuration.Beats` (= BeatsPerBar × Chords.Count), `ScoreBuilder.RiffForModule`, `TimelinePlayer.RiffForModule`, `TimelineImporter.FlattenLeaf`. Degree-locking (`ResolveChordDegrees` + transpose) iterates `cm.Chords` like top-level chords. `btnAddCadence_Click` now creates ONE module via `MakeCadenceChords(key, BuildCadenceChords(...), voiceLead)`. - **Voice-leading / inversions + OCTAVE placement** (`MusicTheory.VoiceLead(chords, baseOctave)` → `(int shift, int inversion)[]`; 2026-06-15): for each chord, choose its **octave shift (−1/0/+1)** AND inversion that MINIMISE movement from the previous chord (`VoicingCost`), **constrained to a register band** (avg pitch within ~a fifth of the first chord, `Band=7`, else +1000 penalty). This fixes the upward DRIFT: before, a cycle of fifths placed each root at its pc within the fixed octave (B→B4=71) and could only invert UP → it climbed an octave by measure 2. Now B is placed an octave lower (shift −1) to stay near. `CadenceChord.OctaveShift` stores it; `GenerateCadence` uses `pg.Octave = m.Octave + c.OctaveShift`. Toggled by the dialog's "conduite des voix" (off ⇒ inversion 0 + shift 0). [[meter-and-snap-rules]] ChordNotes only inverts upward, hence the need for the shift.

- **Degree-locked chords** (`PatternGeneratorModule.Degree`, default -1): -1 = absolute (use Root/Quality as stored); 0..6 = LOCKED to a diatonic degree of `project.Key`. `TimelineScreen.ResolveChordDegrees(oldKey)` re-selects locked chords whenever the key changes (toolbar `ApplyKeyFromToolbar`, `btnTranspose_Click`) so placed chords FOLLOW the tonality without being edited. Smart quality rule: **ROOT always follows the degree's scale position; QUALITY only adapts when the chord was a plain diatonic chord in the OLD key** (`pg.Quality == DiatonicChord(oldKey,deg).quality`) — so I↔i / ii↔iiø flip with the mode, but an explicitly coloured chord (V9/V13, secondary dom V/V, …) keeps its colour and just moves its root. Transpose skips the manual root-shift for locked chords then calls `ResolveChordDegrees`. Chord editor: a **"Degré (dans la tonalité)"** combo ("Manuel" | I..vii); picking a degree sets canonical Root/Quality via `MusicTheory.DiatonicChord(key,deg)` and DISABLES the Fondamentale/Accord pickers. Cadence locks each chord whose **root sits exactly on a scale degree** (chromatic/borrowed roots stay absolute) → whole cadence auto-transposes.
- `MusicTheory.DiatonicChord(key, degree)` = (root pc, quality) of the diatonic degree (tonic forced to a triad). Qualities in `MajorQual/MinorQual` (0,1,6,7,8,9) are ALL real `QualityNames` indices (8 = dom7, 9 = ø7) — only the cadence's final mapping swaps 8→random `DomColour` and tonic→random colour, so `DiatonicChord` uses the raw table directly.
