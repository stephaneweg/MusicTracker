Rules the user set for meter + quantization (2026-06-14), spanning importer / score / riff editor:

- **Snap grid by meter**: simple **x/4 → snap to 1/8 of a beat**; compound **x/8 → snap to 1/6 of a beat** (so triplets survive). Import resolution is **24 slices/quarter** (both importers) — 24÷8=3, 24÷6=4, 24÷3=8 — so triplets are exact integers and never need rescaling.
- **Snap at IMPORT**, not only at display: cleans up live-recorded MIDI jitter. Done in `TimelineImporter.Build` AFTER meter detection (detection reads raw durations), over all tracks' `StartSlice`/`LengthSlices`.
- **Ternary detection**: if the file declares a NON-4/4 meter → trust it, no special handling. If it declares 4/4 (the MIDI default) or nothing → if >50% of note durations are thirds-of-a-beat (triplet feel) → treat as compound **6/8 for now** (later: detect 6/9/12 from the repeating rhythmic motif). A declared-default file → **ask the user** at import via `KeySignatureDialog` (meter row + hint), pre-filling the suggestion.
- **×1.5 is DISPLAY-ONLY**: never rescale note lengths in the DATA (riffs stay 24-res). `TimelineProject.TimeSigScale` (1.5 for ternary 4/4→6/8, else 1.0) is applied only in `ScoreBuilder` (scale-then-snap) and `ScoreView` cursor (`BeatToX(beat*scale)`). `RulerBeatsPerBar()` and the +Riff length are SCALE-INDEPENDENT (`den==8 ? num/3 : num` temps; 6/8→2, 12/8→4) so they stay correct even if a loaded file's TimeSigScale is stale. NOTE: `LoadSqFile` copies project fields one by one — it now restores `TimeSigScale` (was dropped); any new top-level `TimelineProject` property must be added there too.
- **Slice/temps invariant**: 1 temps = 24 slices ALWAYS. 4/4 = 4 temps, 12/8 = 4 temps (NOT 12). Only the subdivision differs: simple croche = 12 slices, compound croche = 8 (the raw triplet-eighth). So the compound temps = dotted-quarter = the SAME 24 slices as a 4/4 quarter — nothing is rescaled, only relabeled.
- **Riff re-segmentation** (`TimelineImporter`, after snapping): a reinterpreted compound bar = `num × spq/3` slices (6/8 = 48 = half a 4/4 bar). The importer cut measures on the declared 4/4 grid (96), so rebuild boundaries on the compound bar length → ONE riff = ONE displayed bar (else a riff spans two). Only when `declaredDefault && ternary`; explicit meters keep the file's boundaries.
- **Compound beaming**: `ScoreView.BeamUnit` = 1.5 display-quarter-beats for x/8 (dotted-quarter = 3 eighths), 1.0 for x/4. Beam groups never cross a bar line. In compound, a beamable run that is BEAT-ANCHORED (`AnchoredOnBeat`: first note on a beat, or right after an on-beat rest/demi-soupir) beams across SEVERAL beats (6/9 eighths, 2 doubles + 4 croches, eighth-rest + 5 croches…), MuseScore-style; off-beat runs and simple meter stay per-beat (`SameBeamGroup`). Runs break at gaps, mid-bar rests, and bar lines (`SameMeasure`).
- Riff editor: `RiffGridControl.MeterDen` (set from `project.TimeSigDen`) drives `SnapFraction()` = 1/6 (compound) or the configured `RiffSnapFraction` (~1/8, simple).

**Why:** the user captures violin via audio→MIDI (no MIDI violin) and imports loose live takes; clean notation needs jitter snapped on a triplet-aware grid, and ternary pieces exported as 4/4-triplets must read as compound without corrupting the playable data.

Related: [[timeline-mode]], [[score-view]], [[riff-note-list-model]], [[violin-audio-capture]].

- **Binary⇄ternary toggle** (`tglTernary` in the toolbar, next to the key): flips x/4⇄x/8 (2/4⇄6/8, 3/4⇄9/8, 4/4⇄12/8) — num ×3 / ÷3, den 4⇄8, scale 1.0⇄1.5. Changes NOTHING in the riffs/sizes; only the score re-renders (ternary = 3 croches beamed by 3; binary = triolets). Timeline ruler is identical either way (RulerBeatsPerBar ÷ scale → same real-quarter count).
- **Ottava** (`ScoreView.ComputeOttava` + `DrawOttavaSpans`): when a measure's highest note rises above the headroom, shift that measure's display DOWN by N octaves (1→8va, 2→15ma, capped; spelling/accidentals kept — only `Spelled` steps change) and draw an italic "8va"/"15ma" + dashed line above the merged span of equal-shift measures, positioned just above the span's highest note. Headroom is staff-dependent: the TOP staff tolerates 4 ledger lines (`OttavaHeadroomTop`=8 steps, it only spills into the top margin — `TopPad`=70 fits it); inner staves stay tight (`OttavaHeadroomInner`=4 ≈2 ledger lines) so they don't hit the staff above. Measure-level (a wide-range measure over-shifts its low notes — known limitation).
- **Score snap is dual-grid** (`ScoreModel.SnapQ`): snaps to the NEARER of the 1/8-beat (binary) or 1/6-beat (ternary) grid — NOT a flat 1/8. Critical so a 1/3-beat note in a SIMPLE meter (scale 1.0) survives as a triolet instead of rounding to 3/8 (the old flat-1/8 snap silently killed binary triplets). Applied after the ×scale, so compound (×1.5) still lands triplet-eighths on a clean 0.5.
- **Ternary parser** (binary-mode triolets, `ScoreView.BuildSlots`): (1) per-beat classification — a beat is ternary if it has a triplet-classified note (`tern` set); (2) `SplitNotes` splits a note at beat boundaries adjacent to a ternary beat so none straddles a triolet — pieces get `TieStart`/`TieEnd` and reclassify (the in-triplet piece is a triplet member tied to its continuation); (3) `DrawTies` draws the tie curves; (4) triplet rests — `AddRests`/`FillRest` fill ternary beats on the 1/6 grid (`TernRestVals`), `DrawRest(..., triplet)` maps the value ×1.5 (1/3→eighth rest, 2/3→quarter rest). Only fires in a simple meter (compound scales triplets to clean eighths so `tern` is empty → no split/ties/triplet-rests). The "3" bracket groups by beat (any note count + rests).
- **Triplet rendering** (`ScoreView.DrawTuplets` + `Classify` triplet table): a 1/3-beat note in a SIMPLE meter (scale 1.0) is auto-detected as a triolet (borrows the ×1.5 base glyph, `Glyph.Triplet`), drawn with a "3" (beamed) or bracket+"3" (not beamed), chunked in 3s. In compound the ×1.5 makes them plain eighths so nothing matches — automatic, no mode flag.
- **Riff editor `DisplayTime`** (display-only, JsonIgnore): the toolbar beats field shows `beats×3` in ternary (so a 2-temps 6/8 bar reads "6"), `beats` in binary; the setter divides back. The riff's real `beats`/slices never change. Editor `MeterDen` (from project) also drives the 1/6-vs-1/8 entry snap.
- **Click a measure in the score** → `ScoreView.MeasureClicked(rawBeat)` → `TimelineScreen.LocateRiffAtBeat`: highlights + scrolls the timeline to the riff covering that beat WITHOUT opening its editor (score stays). `SelectItem`'s early-return now also requires `activeScore == null` so a later box click still opens the editor.

- **Meter combobox** (`cboMeter`, toolbar): lists 2/4,3/4,4/4 (binary) or 6/8,9/8,12/8 (ternary, switches with the styled `tglTernary` pill). Changing the NUMERATOR (same division) re-bars the piece; the toggle changes only the division (temps preserved → no re-bar).
- **Re-segmentation** (`TimelineImporter.ReSegment(project, barBeats, resolve)`): on a numerator change, flattens each track to one absolute slice-note stream (riffs+repeats+silences merged, 24/quarter; drums via `DrumPattern.Generate` grid → `KeyForLane`), re-cuts into `barBeats`-beat bars reusing `BuildMelodicTrack`/`BuildDrumTrack`, rebuilds Items in place (keeps instrument/clef/volume). `barBeats` = temps count = `den==8 ? num/3 : num`. New riffs are added to the library (old ones orphaned, same as import).

- **Transpose** (`btnTranspose` → `TransposeDialog`, `TimelineScreen.btnTranspose_Click`): pick a target key (tonic+accidental+mode, default = current). The interval/mode-remap MATHS now lives in **`MusicTheory`** (2026-06-14, see [[generators-and-cadence]]): `MusicTheory.NearestInterval(fromPc,toPc,direction)` (0 nearest = `up>6?up-12:up` so Do→Sol = −5; 1 up; 2 down) + `MusicTheory.ModeDelta(src,tgt)` (per-pc `tgt[d]-src[d]` remap, null if equal) + `MusicTheory.TonicPc`. Transposes each referenced riff once (deduped); shifts `PatternGeneratorModule.Root` ONLY for **absolute** chords (`Degree < 0`) — **degree-locked** chords instead follow the new key via `ResolveChordDegrees(oldKey)` after `project.Key` is set; skips drum tracks. The tonality combo stays (display + set current key).
- **Modes** (`Engine/Score/MusicalMode.cs`): full mode list for transpose — Majeur/ionien, Mineur naturel/éolien, Mineur harmonique, Mineur mélodique, Dorien, Phrygien, Lydien, Mixolydien, Locrien (each a 7-pc scale). `IsMinorish` (b3) picks the nearest major/minor armure. So harmonic minor keeps the leading tone, dorian lowers only 3+7, etc. — user picks instead of a hardcoded rule.
- **Full mode persists + settable**: `KeySignature.FullMode` (int, default -1 = derive from `Mode`) stores the applied mode. The TOOLBAR key combo now lists ALL 9 `MusicalMode.Names` (not just Majeur/Mineur) and `ApplyKeyFromToolbar` sets `FullMode` = chosen mode + `Mode` = `IsMinorish?1:0` (armure approx). `MusicalMode.Effective(key)` = FullMode if set else `FromKeyMode(Mode)`. Transpose reads `Effective(cur)` as the SOURCE mode → so you can transpose FROM any mode TO any mode; the degree-by-degree remap (`degDelta[src[d]]=tgt[d]-src[d]`) is mathematically identical to going via major. Import builds a fresh key → FullMode -1. (Armure is still the nearest major/minor — true modal armures not done.)

- **BuildLayout end-of-line**: the final bar column (at `totalBeats`) IS the right edge — no MeasurePad/trailing advance/separate barline, else the stretch ballooned a gap before a double barline (the "gap at line end" bug). Multirest column advance = one measure (`SpaceFor(beatsPerBar)`); `DrawMultiRest` draws a FIXED-length bar centered in the (stretched) span so the rest symbol itself isn't stretched. Beams: stems lengthen with flag count (`beamDist` 2.7/3.2/3.6) and `beamGap`=0.92 so 16th/32nd beams don't merge.
- **PDF preview**: "Partition PDF…" now opens a `DocumentViewer` window (zoom + scroll + its own Print button → "Microsoft Print to PDF"), not a direct PrintDialog. Half-size systems allow up to 2/4/8/16/24/32 measures per line.
- **Score PDF export** (`Controls/Score/ScorePdfExporter.cs` + `ScoreView.RenderStandalone`/`stretchTarget`): builds an A4 `FixedDocument` (title = file name, `_`→space; centered) of the checked (♫) tracks, one system per line of N measures (N = largest of 2/4/8/16 whose estimated width fits), each system stretched to FULLY fill the width (final barline at the right edge — `stretchTarget = targetWidth`, no RightPad gap) and rendered at half size (`Scale=0.5`: render at `contentW/Scale`, then `RenderTransform` ×0.5). Reuses `ScoreView` off-screen (glyphs measured, canvas sized explicitly). Output via `PrintDialog` → "Microsoft Print to PDF" (no PDF library — `ReachFramework`/`System.Printing` refs force ISO A4). Risk: Bravura (pack-URI font) must embed in the XPS/PDF.
- **Multi-measure rest** (`ScoreView`, `SlotKind.MultiRest`): a run of ≥2 empty measures → one block (UNIFORM-length thick bar + serifs + count above, centered, capped at `StaffGap*5`, spanning to the real `BarLineX` not `BeatToX` which overshoots). SINGLE staff → collapse EVERY such run (each becomes one compact measure; `collapsedRuns` list drives bar suppression + a one-measure advance in `BuildLayout`). MULTIPLE staves → only the LEADING run, at natural width (no collapse) so bars stay aligned. PDF (`ScorePdfExporter.LineRanges`): single track packs perLine BLOCKS where a ≥2 silent run = 1 block, so a long tacet counts as one measure for the line.
- **MIDI export** (`Engine/Timeline/MidiTimelineExporter.cs`, Export ▸ MIDI): NAudio `MidiEventCollection` (PPQ 480, 20 ticks/slice), one MIDI track per timeline track (drums→ch 10, else 1.. skipping 10), notes from `TimelineImporter.FlattenForExport` (absolute 24/quarter, repeats expanded), tempo + time-sig (REAL quarters/bar = `den==8?num/3:num`, as x/4 so triplet timing stays faithful & round-trips). `PrepareForExport()` adds End-of-Track. Velocity = 100×track.Volume (riffs carry no per-note velocity yet).
- **MuseScore .mscx export** (`Engine/Timeline/MuseScoreExporter.cs`, Export ▸ MuseScore (.mscx); 2026-06-14): native MuseScore-3 XML (opens in MuseScore 3/4). Source = `ScoreBuilder.Build` per checked-♫ track (else all instrument tracks; **drums skipped** — need a drum staff). Works in **display-beat (quarter) space** so the DISPLAY meter is used directly (`<sigN>/<sigD>` = num/den, 6/8 stays 6/8) and ×scale is already applied. One `<Staff>` per part with `<Clef>`(from `TrackScore.Clef`: G/F/C3/C4) + `<KeySig><accidental>fifths</accidental>` (from `KeySig.Derive(Key, Transpose)`, written armure) + title `<VBox>`. Notes → onset-grouped chords; durations rounded to the **3-unit (1/32) grid** (24 units/quarter) and greedy-decomposed into standard values (whole…32nd + 1 dot) via `Vals`; `<tpc>` from a sharp/flat table keyed by the armure. **v1 limits (documented to user):** no ties/tuplets — triplets are APPROXIMATED to the 32nd grid and held/long notes are re-articulated and **truncated at bar lines** (no cross-bar tie). Smoke-tested: well-formed, chords + durations correct. MuseScore export was the deferred menu item; user chose native .mscx over MusicXML.
