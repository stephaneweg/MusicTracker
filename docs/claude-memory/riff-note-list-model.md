Decision (2026-06-13): the **riff** data model moves from a binary slice grid (`SequencerSlice[]`, one bit per note×slice) to a **canonical list of notes** `RiffNote { Note, Start, Length }`. Chords & rhythms KEEP the slice grid — only riffs change.

**Why:** the binary grid can't distinguish two adjacent same-pitch notes from one long note (hence the "détaché" hack of removing a slice). A note list makes them two `RiffNote`s → kills the hack, gives explicit durations, no drag drift.

**Strategy — notes = source of truth, slices = derived.** Bridge both ways so the rest of the system (timeline OR-merge, thumbnails, recorder/MIDI/MuseScore import output) still gets a grid. Lossy direction is notes→slices (reloses adjacency); only used where a grid is genuinely required.

**Interaction model (user-specified):**
- Action starts on mouse-down on the clicked cell; **drag detected on cell-change** (no px threshold).
- Click on **OFF** cell = **draw** mode: lays ON cells; drag extends; if the range **overlaps** (shares a cell with) a same-pitch note → **merge**. "Touche" = overlap, not mere adjacency.
- Click on **ON** cell = **erase/gomme** mode: removes touched cells; mid-note click splits in two, end shortens, start shortens+shifts — all emergent from "erase the cells I touch". Erasing a note's LAST remaining cell (or clicking a 1-cell note) **removes it from the list** (no zero-length notes); a split fragment that later erodes to 0 is dropped too.
- Pitch is **fixed** (no vertical drag); to change pitch, erase & recreate.
- Merge only between **same-pitch** notes.
- Length ≥ 1 (1 slice → Start==End-1).
- **Rendering:** adjacent same-pitch notes (all cells ON, no gap) must show as TWO rectangles with a visible seam (~1px), else the distinction is invisible.
- Save `.sq` as notes; **no backward-compat** with the old slice format required.

**Keyboard entry = hold-to-grow (Phase 2):** holding a note key starts a note at the cursor and GROWS it (DispatcherTimer + Stopwatch). Speed is a FIXED input rate (slices/second), NOT the tempo — `AppSettings.RiffInputSpeed` (default 2 slices/s, settings dialog "Éditeur de riff : vitesse de saisie"); `RiffGridControl.SliceSeconds() = 1/RiffInputSpeed`. Backspace = hold to recede the cursor at the same rate, erasing each crossed column. Release ends the note. POLYPHONIC, per-note model: ONE global cursor (`CursorF()` = growOrigin + growClock/SliceSeconds) advances while any key is held; each `GrowVoice{Key,Note,Start}` draws from its Start to the cursor (length = cursor − Start). On key-down a voice starts AT the cursor, UNLESS a committed same-pitch note ends within < 1 slice of the cursor (positional, not time-based) → it continues that note from its original Start (the committed note is removed). So adding a key mid-chord starts at the cursor, not the chord start. Releasing a key commits that voice with its START and END snapped to the keyboard-entry grid — `AppSettings.RiffSnapFraction` (fraction of a beat, default 1/8, 0 = off; settings dialog "Éditeur de riff : précision de saisie"); `SnapToEntryGrid()` snaps to multiples of `RiffSnapFraction*spb` slices (min one unit so a tap still lands a note). When all released, startSlice = snapped cursor and the clock stops. The grow loop is driven by `CompositionTarget.Rendering` (per-frame, UI thread — NOT a background thread, since WPF rendering must be on the UI thread); each frame it finalises voices whose key is no longer `Keyboard.IsKeyDown` (catches missed KeyUp / focus loss), then advances the cursor and grows. `grows` is keyed by NOTE index (one voice per pitch) with a source `Key` (Key.None = MIDI). **MIDI input** is wired straight into the editor (`MidiIn` opened on Loaded via `ChooseMidiInDevice` = saved recorder device or device 0): NoteOn → `StartGrowNote(note, Key.None)`, NoteOff → `FinishGrowNote(note)`, marshalled to the UI thread — same grow/cursor/snap path as the PC keyboard. BtnMidiRecord temporarily `StopMidiIn()` so the recorder dialog can open the device. **Generic input** abstracted as `INoteSourceProvider` (Controls/NoteSourceProvider.cs): `event NoteOn/NoteOff(int note)`, Start/Stop. Three impls: `KeyboardNoteSourceProvider` (KeyDown/KeyUp + Poll() each frame for missed KeyUp; uses an editor `Func<Key,int> KeyToNote` reading octave/scale/accidental live), `MidiNoteSourceProvider` (`SetDevice(index)` reopens; marshals to UI), `WaveNoteSourceProvider` (live MONOPHONIC MPM, `SetDevice` + `holdSeconds` Func for the change threshold ≈ 1 slice; detection is CHROMATIC — nearest semitone, NOT scale-snapped — the editor passes `() => AudioPitch.Chromatic`; scale snapping is the PC-keyboard letter→degree default). WaveNoteSourceProvider tuning: WaveIn BufferMilliseconds=12/3buffers (low latency; floor = MPM FrameSize), capture thread set to ThreadPriority.Highest (not process-realtime). **`AudioPitch.FrameSize` is now a settable static property** (default 2048) driven by `AppSettings.RiffAudioFrameSize` (applied in `AppSettings.Apply`); settings combo "Fenêtre d'analyse (latence)" {1024/2048/4096} under the **"Analog Input"** section. `DetectPitch` takes an explicit `win` param; `DetectFramePitch` uses `x.Length-start` (so the live path is robust to a mid-session size change). The provider re-allocates ring/frame from `AudioPitch.FrameSize` at Reopen (change takes effect on next 🎤 start) and uses ring.Length/frame.Length internally. **Latency fix (2026-06-14):** the pitch-change debounce ("hold") was indexed on `TempoSliceSeconds` → at slow tempo / coarse `spb` it ballooned to 100-150ms+. Now capped at `MaxHoldSeconds=0.03` (≈2-3 hops), decoupled from tempo. Also: a note attacked FROM SILENCE (curNote<0) is accepted on the FIRST solid frame (`need=1`) instead of 2 — snappier attacks. **Analysis hop decoupled from AudioPitch.HopSize → `hopLen = FrameSize/4`** (analysed 4×/window, CPU bounded since it scales with FrameSize) so confirmation is fast; WaveIn buffer 12→10ms. Settings "Fenêtre d'analyse" now offers **512** (~12ms, "violon/aigus, latence mini") — recommend it for violin (covers ≥86Hz; the inherent floor is ~2 periods of the lowest pitch). Default `RiffAudioFrameSize`=1024 (~23ms); NOTE this only affects fresh configs — an existing settings.json keeps its saved value, so the user must pick 512/1024 in the dialog to benefit. Latency budget @512: buffer ~10ms + window-fill ~12ms + ~1 hop ~3ms ≈ 25ms (near-instant). RiffGridControl "Effacer" now raises a `Cleared` event → TimelineScreen refreshes the module box/thumbnail immediately (not just on leave). DetectSlices/DetectSlicesPoly use a method-local `int Frame = FrameSize`. SettingsDialog is now sectioned: Général / Éditeur de riff / Analog Input (bold header + thin OutlineColorBrush separator). **Onset/re-attack detection** (amplitude envelope, `EnvDecay`): a re-attack on the SAME pitch (louder than env × rise) re-articulates (NoteOff+NoteOn same note) → splits a violin détaché into separate notes; sensitivity = `AppSettings.RiffAudioOnsetSensitivity` (0..1, default 0.5, settings slider "Audio : sensibilité aux ré-attaques (détaché)"), ~70ms refractory. (Octave hysteresis was REMOVED — octave changes use the normal hold.) The OPTION (off by default, settings checkbox "Entrée audio : caler sur la gamme") is `AppSettings.RiffAudioScaleSnap`: when on, audio snaps to the editor scale (`EditorScaleMask`); off = chromatic. The editor passes `() => RiffAudioScaleSnap ? EditorScaleMask() : AudioPitch.Chromatic` as the provider's scaleMask. RiffGridControl wires all three NoteOn→`StartGrowNote(note, tempo, merge)` / NoteOff→`FinishGrowNote(note)` (merge=true ONLY for the PC keyboard → continue/merge same-pitch via MergeAdd + re-press resume; merge=false for MIDI **and** AUDIO → successive notes stay SEPARATE, just snapped, plain notes.Add, no continue). Clear (Effacer) also resets the horizontal scroll to 0. MOUSE drawing does NOT auto-scroll horizontally (the `FollowCursor` call was removed from the mouse-draw path) — only keyboard/playback follow the cursor. `FollowCursor` is now a PAGE-TURN (like the score): within one measure of the right edge (or off the left) it jumps the cursor to ~30px from the left (was pin-to-middle). `EnsureCols` grows the grid by WHOLE MEASURES (`ceil(minCols/(spb·BeatsPerBar))·BeatsPerBar` beats), not per-beat. **Metronome locked to the cursor during a tempo take**: `OnGrowFrame` clicks `metro.Tick(downbeat)` exactly when `floor(CursorF()/spb)` crosses a new beat (`metroCursorBeat`, initialised at take start so start-on-beat clicks immediately) → the audible beat matches the displayed beat line; the free DispatcherTimer skips while a tempo take runs; metro WaveOut DesiredLatency 100→60ms. The click is fired slightly EARLY (`MetroAnticipateSec`=0.05s look-ahead on the cursor) so it SOUNDS on the beat despite audio-output latency. (A dedicated Monitor.Wait thread was considered but gives no precision gain — Windows wait/timer granularity ≈ the render frame ~15ms — so it stays cursor-frame-driven.) (grows keyed by note, no source field; OnGrowFrame calls `kbSource.Poll()`). Device pickers are two combos in the keyboard toolbar (MIDI in / Audio in), remembered in `AppSettings.RiffMidiInDevice` / `RiffAudioInDevice`; MIDI is always live (started on Loaded), audio is toggled by the 🎤 button (waveSource.Start/Stop). Opening a recorder dialog frees the device (uncheck 🎤 / midiSource.Stop()). Note keys are handled at the hosting Window's PreviewKeyDown/Up (hooked on Loaded), gated by `IsVisible` and `TypingElsewhere()` (no TextBox/ComboBox focused) — no focus-stealing. Cursor advance rate depends on the SOURCE that opened the session: PC keyboard = fixed `InputSliceSeconds` (RiffInputSpeed); MIDI/audio = `TempoSliceSeconds` ((60/editorBpm)/spb, real-time). The editor tempo is an editable BPM field (txtTempo) → `editorBpm`, persisted in `AppSettings.RiffEditorTempo` (default 100); it also drives the ▶ preview (FlowContext.Bpm). `StartGrowNote(note, tempo)` sets `cursorTempo`; Backspace stays input-speed. A MIDI/audio session is a continuous TAKE (`tempoRun`): the cursor keeps running through RESTS (silence) until explicitly stopped — `OnGrowFrame`/`FinishGrowNote` don't settle while `tempoRun`. Stop via the ■ Stop button (`BtnStopRun_Click`→`EndRun`/`StopRun`) or the Escape key; any manual edit (mouse/Space/Backspace/Clear/▶) also ends the take first (`EndRun`). Keyboard sessions still stop on note release (not a take). On Stop, `StopRun` trims the riff length UP to the started measure (ceil of cursor extent to a whole `spb*BeatsPerBar`-slice measure), then raises a `RecordingStopped` event; TimelineScreen handles it via `RefreshEditedRiffBox()` (thumbnail-only, or RefreshTrackLane if the length changed) so the module box/thumbnail update immediately (vs the deferred on-leave `CommitRiffEditor`). Duration toolbar buttons (Ronde…2×croche / dotted / tuplet) were REMOVED — duration is now the cursor advance; Space inserts a rest of one snap unit (`RestStep` = RiffSnapFraction*spb). The standalone recorder dialogs (RiffRecorderDialog/MidiRecorderDialog) were DELETED — recording is integrated live in the editor via the source providers. (AudioPitch.DetectSlices/DetectSlicesPoly/SnapToGrid + MetronomeProvider + AppSettings.Recorder are now dead code, kept for now.) **Audition (MIDI echo) is toggleable**: kbBar checkbox "Écho MIDI" → `SetAudition` sets `auditionEnabled` (default `AppSettings.RiffAudition`, persisted) and `MidiNoteOn` no-ops when off (releases held notes via AllNotesOff) — turn it off when monitoring a live instrument on audio in (you already hear it). Audition while editing (note keys + mouse draw) is sounded through the **Windows MIDI synth** (`NAudio.Midi.MidiOut` device 0, GS Wavetable) — native polyphony, low latency. The audition PROGRAM matches the track's instrument: `Configure`/`SetPreviewInstrument` take an `instrumentIndex` (= track.Instrument, 0..127 GM program; 128 = drum → channel 10); `SetAuditionInstrument` sets `auditionProgram`/`auditionChannel` and `ApplyAuditionProgram` sends a Program Change to the MidiOut (re-sent when the instrument changes). So the timbre approximates the SoundFont preset (both GM-indexed), NOT a fixed patch (the ▶ preview still renders the real `previewInstrument`, which in the timeline = `InstrumentCatalog.Create(track.Instrument)`). Horizontal scroll pins the cursor to the viewport centre once past halfway (continuous, not page-jump). A partially-held final cell counts only if filled ≥ `GrowFillThreshold` (currently **0.75** — a named const, user may ask to tune it). Replaces the old fixed-duration EnterNote + détaché hack. One growing note at a time; Space still inserts a rest of the toolbar duration.

**Phased plan:** 1) model + bridges (DONE — `Engine/RiffNote.cs`: `RiffNote` + `RiffNotes.FromSlices/ToSlices/LengthOf`, zero wiring/regression). 2) editor `RiffGridControl` (DONE): note-list model, one rounded rect per note (1px inset each end = automatic 2px seam between adjacent notes), mouse draw/erase/merge/split, hold-to-grow keyboard entry. Still bridges to slices at the Riff boundary (storage unchanged until Phase 4). Toolbar duration radios now only drive Space-rest stepping. 3) playback `RiffPlayer` (Flow/FlowPlayer.cs) schedules notes (DONE — event-driven: per-slice attackAt/releaseAt built from riff.Notes; release-then-attack at a boundary re-articulates adjacent same-pitch notes; ctx.Reverse mirrors). 4) persistence (DONE — `Riff` stores `Notes` (List<RiffNote>) + `LengthSlices`; `Slices` is a `[JsonIgnore]` computed bridge (get=ToSlices, set=FromSlices) so slice-consumers still work; a set-only `[JsonPropertyName("Slices")] LegacySlices` reads OLD .sq files (Slices→Notes) without re-serializing. Editor loads/saves `riff.Notes`+`LengthSlices` directly; ScoreSlicing import builds RiffNotes with full durations — détaché hack GONE). 5) timeline (DONE — `TimelinePlayer` flattens each track into per-slice `AttackAt`/`ReleaseAt` event lists (from riff.Notes scaled to Spb=24) instead of a merged slice grid; `SynthTrack` is event-driven with per-track Active/Retrig/Applied (Applied persists across Read calls / catches up across buffers) → re-articulation in the timeline too. Resample removed.). Dead code (only the deleted recorder dialogs used it): `AudioPitch.DetectSlices/DetectSlicesPoly/SnapToGrid` + `AppSettings.Recorder`/`RecorderSettings` (NOT MetronomeProvider — used by the metronome) — pending cleanup task.
