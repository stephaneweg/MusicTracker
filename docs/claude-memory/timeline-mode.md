Goal (user's design): replace the multi-layer **sequencer** (NOT the riffs, NOT the graph) with a **timeline / arrangement** editor.
- Two **track TYPES** (`TimelineTrackType`): **Instrument** (header: instrument combo + base volume; holds Riff / chord-Pattern / Repeat) and **Drum** (header: base volume only — instrument is implicitly the drum kit; holds DrumKit generators / Repeat). Variable count, add/remove. The +module toolbar buttons enable per selected-track type (`UpdateToolbar`). `TimelineTrack { Type; Instrument; double Volume (base); List<VolumePoint> VolumeAutomation; Items }`.
- **A "volume" sub-track ABOVE each track**: `VolumeAutomation` = list of `VolumePoint{Beat,Volume}` (changes at T); rendered as a thin lane (`MakeVolumeLane`, base line + dots, click adds a point). Multiplies/overrides the base volume over time (applied at playback, Phase 2).
- Drop **riff / chord-pattern (Pattern) / drum-kit / Repeat** modules along time. Position & width **∝ duration in beats** (reuse `FlowModuleControl.PxPerBeat`=60).
- **One global cursor** reads modules by absolute time. **Silence is RELATIVE**: each `TimelineItem.SilenceBefore` (beats, hidden from the user, set by drag) = the rest before it; absolute start = sum of (SilenceBefore + length) of preceding items (walk). Player waits SilenceBefore then plays the item (except when auditioning a single module → skip its leading silence). Model is now relative (NOT absolute StartBeat) — `SequenceLength`/`GroupLength`/`TrackEnd` walk the list; the renderer walks a cursor to get each item's absolute X.
- **Drag overlap rule (Phase 3)**: when a dragged module overlaps an in-place one, the drop point's half decides order — overlapping the FIRST half → insert BEFORE it (push it + following right); overlapping the SECOND half → insert AFTER it (push the following right). Then re-pack with no overlap (adjust SilenceBefore of the following).
- **One tempo track on top** (global): main tempo + tempo changes at points.
- **Repeat = a CONTAINER** (repeats its inner items N times, or loops to the end) — NOT the graph's port-based Repeat. It holds ONE sub-track of LEAF modules + gaps (silences), **NO nesting** (no repeat in a repeat), and **NO padding** so its inner timeline aligns exactly with the outer one (group span = max inner end). Inner modules are drag-movable (Phase 3). Display: a translucent backdrop spanning the Repeat's FULL ×Count span (real played time = `ItemLength` = groupLen × Count); inner modules are TILED across the cycles below a reserved title strip — cycle 0 editable (full opacity, interactive), the repeated copies dimmed ghosts (opacity 0.4, non-interactive). E.g. R1 R2 ×2 → R1 R2 R1(ghost) R2(ghost). (This is the final design after a few iterations: was tiled→compact→full-width-once→tiled-ghosts at user request.) `DispLen` in TimelineScreen == `ItemLength`. Adding into a Repeat: select it, then +Riff/+Accords/+Batterie append into its sub-track AND select the new sub-item (re-select the Repeat to add several); +Repeat is blocked inside.
- Drag modules left/right (no overlap → push following); resizing/editing a module (or a Repeat's contents) grows it right and shifts the following ones.
- **Module editor in the BOTTOM panel** (tracks on top, editor below, large/resizable), DEDICATED per type (NOT the graph node control): **Riff** = riff combo + "Nouveau" + the inline riff piano-roll, now a dedicated `Controls/RiffGridControl` (NO LONGER the embedded `SequencerScreen`) — a piano-roll modelled on `RhythmGridControl`: 96 note rows (note idx = `Utils.Frequencies` key, MIDI = note+12), grid lines drawn once + one rectangle per ON note, beat/measure guides, `Configure(riff, instrument)` / `CurrentSlices()` / `Spb` / `GridChanged` (persists live to the riff). `CommitRiffEditor` just stops its preview. **Chord/Drum** = left = the node-like fields, right = the manual rhythm grid (visible only when style = "Personnalisé"). The grid is the reusable `Controls/RhythmGridControl` (extracted from PatternRhythmDialog; the dialog now hosts it too) — `Configure(...)` + `CurrentGrid()`/`Spb` + `GridChanged` event so edits persist live (`SetCustom`). A module box shows only title + info.
- **Extracted UserControls** (`Controls/TimelineEditor/`): `VolumeLaneControl` (taller volume sub-track — click=add point, drag=move point on both axes, right-click=delete; mutates `track.VolumeAutomation`), `ModuleBoxControl` (leaf module box, reused for Repeat inner modules; `Configure(title,info,w,h,selected,interactive,opacity)` + `Selected` event), `RepeatItemControl` (compact Repeat backdrop+title; `TitleStrip` const + `Selected`), `TempoLaneControl` (tempo lane), `MeasureRulerControl` (measure-number ruler — thick tick+number per bar, half-tick per beat). The tracks area (Grid.Row=1) now has a FROZEN top row: a "Mesures" corner above the header column + the measure ruler above the lanes; `laneScroll_ScrollChanged` syncs header vertical AND ruler horizontal. `TimelineScreen` stays the layout orchestrator (computes positions/widths via `DispLen`, wires `Selected`→`SelectItem`). `VolLaneH`=48.
- **Tempo lane editing** (`TempoLaneControl`): double-click a BPM marker → inline TextBox (Enter / focus-out commits, Esc cancels); double-click empty → add a tempo at the nearest beat, in edit mode; added tempos (index>0) get a ✕ to delete; the initial tempo (beat 0, index 0) is not deletable. Mutates `project.Tempo` in place.
- **Item deletion** (✕ on `ModuleBoxControl` and `RepeatItemControl` → `TimelineScreen.DeleteItem`/`RemoveAt`): whatever follows stays in place — the freed time (`deleted.SilenceBefore + DispLen(deleted)`) is added to the NEXT item's `SilenceBefore` in the same list. Deleting the last module of a Repeat shrinks the Repeat (groupLen recomputes) and transfers the freed time to the track item that follows the Repeat.
- **Track selection**: click a header (PreviewMouseLeftButtonDown, re-renders only if changed so header controls stay usable) or an empty lane area → `SelectTrack`.

Decisions made: REPLACED the sequencer; instrument PER TRACK. `SequencerScreen` is now DELETED — the riff editor everywhere (timeline bottom panel AND the graph's `RiffEditorWindow`) uses `Controls/RiffGridControl`. `.seq` open + the SequencerScreen file are gone. (Orphaned after removal, pending cleanup: `SequencerWaveProvider`/`SequencerLayerWaveProvider`/`SequencerProject`/`MidiOutPlayer`.)

Reuse: modules (PlayRiff/Pattern/Drum + their `Generate→Riff`, durations), `Engine/Flow/ModuleDuration.Beats(module, resolveRiff)` (shared duration helper), `FlowModuleControl` param editors (+ the ✎ edit dialogs), `RiffPlayer`, `LoopingRiffProvider`.

THE hard part = playback: the graph `FlowPlayer` can't do a GLOBAL mid-piece tempo (parallel branches each carry their own tempo). So Phase 2 needs a dedicated **TimelinePlayer** that advances in absolute beats with a **tempo map** and mixes all active tracks' RiffPlayers (one cursor). Repeats are expanded inline for playback.

Model (`Engine/Timeline/TimelineProject.cs`): `TimelineProject { List<TempoChange> Tempo; List<TimelineTrack> Tracks }`; `TimelineTrack { Name; int Instrument (InstrumentCatalog idx, DrumIndex=drum); List<TimelineItem> Items }`; `TimelineItem { double StartBeat; FlowModule Module (leaf) | RepeatGroup Repeat }`; `RepeatGroup { int Count; bool Loop; List<TimelineItem> Items }`. Static helpers `ItemLength`/`GroupLength`/`TrackEnd` (beats).

IMPORT (done): toolbar "Importer MIDI/MuseScore…" → `Engine/Timeline/TimelineImporter.Build(Score, measuresPerRiff, slicesPerBeat, importVolume)` → `{Project, Riffs}`. One track per staff (melodic = instrument track of PlayRiff modules with `Instrument`=GM program; percussion = drum track of custom DrumPattern modules); identical consecutive drum bars collapse into a Repeat (Count=run); silences become each next item's `SilenceBefore` (items aligned by absolute beat via a running cursor); dynamics → base `Volume` + `VolumeAutomation` points WITHOUT splitting the riff (one riff per measure-group; the timeline import dialog hides the volume checkbox via `ImportGraphOptionsDialog.HideVolumeOption()` and always imports volume). Meter (beats/measure) is READ from the file: MidiImporter reads `TimeSignatureEvent` (4/4 only if absent), MuseScore gives measure boundaries. The pure slicing helpers (GetOrCreateMeasureRiff / BuildDrumLaneGrid / SameGrid) were moved out of MusicScreen into shared `Engine/Timeline/ScoreSlicing.cs` (used by both the graph import and the timeline import). Parsing via `MidiImporter.Load`/`MuseScoreImporter.Load`. TimelineScreen import REPLACES project content + adds riffs to RiffLibrary.

PERSISTENCE (done): `.sq` files. `TimelineScreen.FileExtension=".sq"`, `Save` serializes `TimelineDocument { TimelineProject Project; List<Riff> Riffs }` with `JsonSerializerOptions { IncludeFields = true }` (the timeline model uses public FIELDS, so IncludeFields is REQUIRED), `LoadFile(path)` deserializes + replaces RiffLibrary + project. MainWindow.OpenPath routes `.sq` → TimelineScreen.LoadFile. (Note: `.sq` = timeline, `.seq` = the old sequencer — different extensions.)

PLAYBACK (Phase 2 DONE): `Engine/Timeline/TimelinePlayer.cs` — a mono WaveProvider16. Flattens each track ONCE into a SequencerSlice[] at 24 slices/beat (repeats expanded, silences via SilenceBefore, each module's riff resampled from its spq), then a global cursor advances slice-by-slice using the tempo map (samples/slice = (60/bpm)/24*rate, recomputed per slice), synthesizing per-note voices like RiffPlayer (clone template, GetNext(Utils.Frequencies[note]), DoRelease/ring-out), scaled by each track's base volume × automation (linear interp, override-not-multiply). Instrument = InstrumentCatalog.Create(track.Instrument) (drum track = drum kit). TimelineScreen: ▶ Lire button → WaveOutEvent + DispatcherTimer moves a playback cursor (Rectangle on a cursorCanvas overlaying lanePanel, auto-scrolls). StopAudio/StopPlayback wired.

PHASES: ① model + display + basic add/select/edit (DONE). ② TimelinePlayer (tempo map + cursor + multi-track mix). ③ editing (drag, resize, no-overlap push, Repeat container contents, tempo changes). ④ import-into-timeline + persistence (.tl), then remove the old sequencer.
