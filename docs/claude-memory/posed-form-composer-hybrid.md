Built 2026-06-18. A hybrid composition path: the **V1 Timeline `GhibliComposer`** (posed 6-section form: intro · thème · ré-expo · développement · recap · outro, with RefitTheme/BuildVariations) now borrows its **theme melody + chord grid from a V2 corpus model** instead of the hand-written Lydian/modal generator. Major/minor only, 4/4, 1 chord/bar.

- **Façade**: `ComposerV2Base.MakeThemeAndChords(model, seed, bars, minor, tonicPc, charOverride, section)` (Engine/ComposerV2/ComposerV2Proto.cs) — minimal session setup then calls the virtual `SampleProg`+`GenerateLine`; returns chords as `(rootPc, quality)` and theme as `RiffNote`s. **`Cell.Canon` == V1 `PatternGenerator` quality** (same enum) and `Cell.Root` = semitone offset from tonic → no quality mapping needed.
- **Dual-mode `GhibliComposer`** (Engine/Timeline/GhibliComposer.cs): parameterless ctor = pure V1 (still used by CreateStructureDialog fallback); `(modelFile, displayName)` ctor = hybrid. `ComposerV2Runtime.CreateFor(modelFile)` picks the right V2 engine by filename. Intro/theme/outro chords come from the model's **section-conditioned** harmony; intro gets a short V2 melody; V1 refines the intro→theme transition (intro cadences on V + last intro note leads by step into theme head).
- **Question/answer rhetoric** (helper `EndOn` retunes a phrase's last note to a target degree): THÈME ends on a "question" = V sus4 chord (`questionChord`) + melody on the **supertonic** (open); RÉ-EXPO = the "answer" on the counter instrument, resolved to the **tonic**. DÉVELOPPEMENT is a **dialogue** via a per-rep `devMode[]`: 0 = QUESTION (lead alone, open on local V), 1 = ANSWER (counter alone, resolves to local tonic), 2 = TOGETHER (both voices, counter harmonised a diatonic 3rd below, resolved). Reps alternate Q/A but **sometimes sing TOGETHER**, and the dev **culminates together** (last rep mode 2; `devMult>=4` may add a mid together). `devCh` resolves to local tonic on answer+together reps, stays open (local V) on questions. Dev sub-sections are per-rep ("Développement 1/2/…").
- **Overlap / "fondu"** at Q↔A hand-offs: per-section riffs CLIP a note at the boundary, so extending the last note does nothing — instead the ending voice gets a short LINGER note (half-bar) that STARTS on the next rep's downbeat on its own track, so the two briefly overlap (a fade from one voice to the other). Visible as a `+1` note in the "wrong" voice's dev sub-section.
- **Per-STYLE backing** (fixes "every style sounded like Ghibli"): `ComposerV2Base.MakeBacking(model, seed, minor, tonicPc, charOverride, segments)` calls `Configure()` (style instruments + tempo) then the style's OWN virtual `RenderAccomp`/`RenderBass` per section segment → Vivaldi's motor + harpsichord/continuo @ ~111, Bach harpsichord, Ghibli arpeggio/flute, etc. The hybrid uses its `LeadProgram/CounterProgram/AccompProgram/BassProgram` + `Bpm` instead of the old hardcoded Hisaishi arpeggio + Ghibli instrument set. Tempo follows the style unless the dialog tempo ≠ 60. The glockenspiel "Cloches" build-up is now Ghibli-only (`v2ModelFile` contains "ghibli"). (Bach solo renders no accomp — authentic; the pad+bass still give harmony.)
