Second style on the shared **Composer V2** engine (see [[ghibli-composer-v2]] for the engine: `ComposerV2Base` + `CorpusAnalyzerV2` + the `CorpusModelV2` format + Witten-Bell back-off sampler). Models Bach's SOLO writing (unaccompanied + solo-with-continuo). Built 2026-06-16.

**Corpus** = `corpus/bach/solo_cello` (36 = 6 cello suites × 6 mvts), `corpus/bach/solo_violin` (31 = 3 sonatas + 3 partitas), `corpus/bach/solo_flute` (4 = BWV 1013). All UNACCOMPANIED solo MIDI. Digested via `MidiImporter` → the same V2 analyzer. (Distinct from [[bach-wtc-corpus-analysis]] which fed the V1 canonical composer.)

**Sibling V2 model — `bach_clavier` (WTC), 2026-06-17.** `analyze_bach_clavier.ps1` (repo root) → `AnalyzeToFile("corpus/bach/wtc", Data\bach_clavier_model_v2.json, corpus\bach_clavier_model_v2_report.md)`. **61/72 files** (11 Book-I MIDIs are corrupt/non-standard → NAudio parse errors "Invalid chunk header"/"Read too far"/"Unable to read beyond end of stream" — a file problem, not analysis; fixable only by a lenient loader). 32 major / 29 minor (all 24 keys × 2 books). Character enjouée 50.8% / modérée 39.3% / calme 9.8% / majestueux 0% (active preludes+fugues, few slow, not march-like). Functional fifth root-motion (ii→I, V→I, I↔IV, I↔V). **Chord-tone ≈ 68-69%** (vs solo's ~32-45%) — WTC is REAL keyboard polyphony (2-4 voices) so chord detection is far more reliable than on the monophonic solo arpeggios.

**`BachClavierComposer : ComposerV2Base`** (`Engine/ComposerV2/BachClavierComposer.cs`, 2026-06-17). `Movement` prop "prelude"|"fugue" (null=random); getters ChosenTonicPc/Minor/Movement. Harpsichord (GM 6). tonal major/minor.
- **prelude** (2 parts RH/LH): per bar, RH = continuous broken-chord 16ths (chord tones up-then-down wave, à la WTC Bk I Prélude 1), LH = bass root + fifth in half notes; over `ClavierPlan` (functional circle-of-fifths + ii-V-V-I) → rolled Picardy close. Verified E-major arpeggio `64 68 71 76 71 68…`.
- **fugue** (3 parts SOP/ALT/BASS): a hardcoded entry plan `roots={0,0,7,7,0,0, 5,10,3,8, 0,0, 2,7, 0,0,7,0}` (I-bars take a tonic subject, V-bar takes the answer). SUBJECT + COUNTERSUBJECT = two `GenerateLine` calls over [I,I] (`Trim2Bars`). EXPOSITION ACCUMULATES: alto subject ALONE (bars0-1) → soprano answer +4 scale-steps=a 5th up + alto CS (bars2-3) → bass subject 8ve down + soprano CS + alto filler (bars4-5). Then EPISODE (SequenceMotif = subject head sequenced down a step + WalkBass + FillHarmony), middle entry (soprano subject, tonic), episode, FINAL entry (soprano) over a tonic PedalBass → cadence+Picardy. Free voices = `FillHarmony` (plan chord tones, sustained) so it stays consonant. `PlaceLine(line, startBar, part, scaleSteps, octaveShift, vel)` transposes entries; counter-subject transposed to MATCH the entry it accompanies (+4 over the answer). Verified notes-per-voice-per-bar accumulation. Honest limit: free voices are sustained chord tones (subject + chordal accompaniment), not full strict 3-voice counterpoint.
- **Scripts:** `analyze_bach_clavier.ps1`, `compose_bach_clavier.ps1 [seed] [prelude|fugue]` → `corpus/bach_clavier_<tag>.mid`, `verify_fugue.ps1` (notes/voice/bar). Lock note: close any media player on the .mid before regen.

Shared inner loader = `AnalyzeFileInto(file, label, model)`. Script `analyze_bach_solo.ps1` (repo root) → `MusicTracker/Data/bach_solo_model_v2.json` (~4.4 MB) + `corpus/bach_solo_model_v2_report.md`. **PS-reflection gotcha:** a single `string[]` arg must be wrapped as a 1-element `object[]` (`$argv = New-Object 'object[]' 1; $argv[0]=[string[]]$dirs`) or `@([string[]]$dirs)` unrolls into N args → "Parameter count mismatch".

**Validated Bach findings (from-scratch, vs Ghibli):** 37 maj / 34 min; root motion = **fifth-based/functional** (V→I 6%, I→V, ii→V, I→IV, IV→I — circle of fifths) NOT Ghibli's plagal/modal; **leading tone PRESENT** (maj deg7=9.8%, min raised-7=4.8%) where Ghibli avoids tendency tones; lots of **passing/figuration** (chord 37.9% + passing 17.6% + appogg 10.7% + neighbor 7.4%); tempo **BIMODAL** (112+ = 62% fast dances/preludes vs <66 = 22.5% sarabandes/adagios); meters 3/4 38% + 4/4 37% + compound 12/8·6/8·9/8·3/8 (dances). The melody-CHARACTER root context (see [[ghibli-composer-v2]] Round 13) generalized cleanly: enjouée 56% / calme 24% / modérée 20%.

**`BachSoloComposer : ComposerV2Base`** (`MusicTracker/Engine/ComposerV2/BachSoloComposer.cs`). Public props: `Instrument` ("violin"/"cello"/"flute" or null=weighted pick), `WithContinuo` (bool). Configure: collapses corpus modes to plain **major/minor** (Bach is tonal, not modal — `scale = Major/MinorScale`), picks instrument → idiomatic open-string tonic set + range + clef + GM program (violin 40 / cello 42 / flute 73), bpm 66 (prelude) / 72 (continuo). Harmonic plan `BachPlan` = I → **diatonic descending-fifths circle** (Fortspinnung sequence; `[0,5,10,3,8,2,7]` minor / `[0,5,11,4,9,2,7]` major) → ii–V → **dominant-pedal bar** → V–I. Chord qualities = **strictly DIATONIC triads** via `DiatonicQuality(root)` (minor: i ii° III iv **v** VI VII — v stays minor), V forced major/dom7 ONLY at the cadence (`cadentialDominant`), final tonic forced **maj = Picardy**. `ChosenTonicPc`/`ChosenMinor` public getters expose the picked key. Public getters + props are the UI hook.
- **Solo unaccompanied** → `RenderPrelude`: per bar a figuration outlining the chord as **IMPLIED POLYPHONY** — `BuildLadder` (chord pitches stacked bass→top across the range), then a low pedal (ladder[0]) anchoring the STRONG beats under an arching upper broken-chord voice. Note DURATIONS are model-driven (Round-2 fix below), not a fixed grid. Pedal bar = bariolage (fixed top note alternating with a moving lower voice, even 16ths). Ends on an arpeggiated held Picardy tonic. Implied polyphony verified: violin C-min first bar pedal-60-on-strong-beats + upper arch = textbook compound melody.
- **2026-06-16 fix — melody rhythm was monotone (320 equal 16ths).** `RenderFigurationBar` now draws each note's duration from the corpus `model.MelodyRhythm` chain (full 9-tier back-off ladder, contexts ALIGNED to the analyzer's tier order — pad missing r4–r6 history with "^", section "body"), clamped to 16th..quarter (6..24 slices). Result: mixed 16th/8th/dotted-8th/quarter (violin ~183/57/1/5; cello ~143/56/7/11) — varied, still implied-polyphonic. The pedal/bariolage bar stays even 16ths for contrast.
- **Solo + continuo** → `RenderContinuo`: model-driven melodic `GenerateLine` on part 0 + `ContinuoChords` (harpsichord prog 6, broken-chord eighths, mid register) + `ContinuoBass` (contrabass prog 43, walking quarters root–3rd–5th–stepwise-approach-to-next-root). Verified 3 channels.

- **2026-06-17 fix — output sounded "atonal" in minor (Db, Eb-then-E cross-relations).** TWO causes: (1) trusting the model's `QualityByDegree` — chord detection on a single arpeggiating line invents 7ths/extensions → chromatic chord tones clashing across bars; fixed by using DIATONIC triads only (above). (2) **Enharmonic mis-spelling in `MuseScoreExporter`**: `Tpc(midi, bool flats)` spelled ALL black keys with the key's single flat/sharp bias, so a d-minor leading tone C# printed as Db, Picardy F# as Gb. (`DerivedKey.LeadingSharpPc` existed but was never threaded to the speller.) Fixed `Tpc(midi, int spellCenter)`: spell each black key toward the TONIC on the line of fifths — `spellCenter = keySigFifths + (minor? 3 : 0)` (minor tonic sits 3 fifths above its key sig), pick sharp vs flat by min |tpc − (14+spellCenter)|. Generalizes correctly for major+minor, fixes ALL minor-key score exports (Ghibli too). Verified d-minor: pitch set = D E F G A Bb C + C# (cadential V) + F# (Picardy); `.mscx` Db(tpc9)=0, C#(tpc21)=13, F#(tpc20)=7. Example: `corpus/bach_solo_dmin.mid/.mscx` (probe_dmin.ps1).
- **2026-06-17 feature — DANCE rhythms (movements) instead of a generic figuration.** User: "use known rhythms (sarabande, courante, allemande, chaconne…)." Bach's solo works ARE dance suites. `Movement` public prop (+ `ChosenMovement` getter); `PickDance` picks one of {allemande, courante, sarabande, gigue, menuet, bourree, gavotte, chaconne, prelude}. `SetMeterForDance` sets meter+tempo: allemande 4/4·68, courante 3/4·116, sarabande 3/4·58, gigue 6/8·116, menuet 3/4·126, bourree 2/2·120, gavotte 4/4·104, chaconne 3/4·66, prelude 4/4·66. **Engine was 4/4-hardcoded (`const Bar=96`)** → added instance `barSlices = num*96/den` (3/4→72, 6/8→72) + `beatUnit` (den==8?36:24) + `beatsPerBar`; all solo render uses these, NOT `Bar`. `DanceRhythm(d)` = the characteristic per-bar duration template (slices): sarabande/chaconne `{24,36,12}` (q·q.(beat-2 agogic stress)·8), courante `{12×6}` running 8ths, menuet `{24,12,12,24}`, gigue `{24,12,24,12}` lilt, bourree `{12,12,24,…}`, gavotte `{24,24,12,12,24}`, allemande `(12,6,6)×4` flowing; prelude rhythm=null → model-`MelodyRhythm`-driven varied. `RenderFigurationBar(cell,abs,pedal,int[] rhythm,vel)` walks the template, implied bass on beat onsets (`bassEveryBeat` for fast dances; downbeat-only for slow/elegant ones), arching upper voice between. Chaconne uses `ChaconnePlan` (descending-tetrachord ground `[0,10,8,7]` min repeated). Bariolage pedal bar kept only for prelude+fast dances. WithContinuo forces a 4/4 dance (GenerateLine is 4/4-bound). Verified meters+rhythms: sarabande 4/6/2-16ths, gigue 4/2 lilt, courante running 2/16, etc. **Scripts:** `compose_bach_dances.ps1` (one piece per dance → `corpus/bach_<dance>.mid`), `compose_bach_solo.ps1 [seed] [inst] [solo|continuo] [movement]`.
