# Rapport — 2026-07-28 (run #4) : export MusicXML, publié en 1.4.0.1

Premier run du **pipeline multi-agents** (fonctionnel → technique → développement → tests). Trois analyses ont tourné en parallèle sur d'autres sujets ; leurs documents sont commités, prêts à coder.

## Feature livrée : export MusicXML

**Pourquoi.** Le rapport précédent la recommandait explicitement pour « le prochain run » : déterministe, donc validable sans oreille — ce qui compte dans un pipeline automatisé. Vérification faite dans le code : aucune trace de MusicXML ; les seules sorties de partition étaient `.mscx` (natif MuseScore) et PDF (image figée). Aucun format d'échange portable.

**Ce qui a été fait.** Un `MusicXmlExporter` jumeau de `MuseScoreExporter`, alimenté par le même `TrackScore` que produisent déjà la vue partition, le PDF et le `.mscx`. Format score-partwise MusicXML 4.0, `divisions=24`. Mêmes règles de sélection de pistes, même titre, même partition qu'à l'écran. Entrée « MusicXML (.musicxml)… » dans le menu Export, 3 clés de localisation × 7 langues.

**Gain de qualité au passage** : une note qui traverse une barre de mesure est écrite **liée**, là où l'export `.mscx` la tronque. Le défaut existe toujours dans `.mscx` — corrigé séparément, pour ne pas risquer une régression sur un export en service.

Rien d'autre n'a bougé : ni `ScoreBuilder`, ni `MuseScoreExporter`, ni le format `.sq`. Aucune migration, donc aucune régression possible sur l'existant.

## Incidents rencontrés

1. **Limite mensuelle atteinte en cours de route.** Les quatre runs ont été coupés. La reprise (`resumeFromRunId`) a rejoué depuis le cache tout ce qui était déjà fait — seule l'étape interrompue a été refacturée. Le développement, terminé, n'a pas été refait.
2. **Le pipeline a conclu « rouge » alors que les tests n'avaient jamais tourné** — l'agent avait été coupé, pas mis en échec. Le script ne distingue pas *test échoué* de *test empêché*. Dans un run non surveillé, cette confusion aurait annulé du code sain. **À corriger.**
3. **Build Release cassé par des packages NuGet disparus** (NAudio, System.Buffers et 12 autres). Sans rapport avec la feature ; réparé par une restauration depuis le cache global. Le build Debug passait, lui — d'où une détection tardive : les agents ne compilent qu'en Debug.
4. **La release s'est arrêtée avant de publier au dépôt releases.** Installeur et `latest.json` étaient produits mais non commités, donc invisibles pour l'auto-update. Terminé à la main. Cause probable : `git` écrit sur stderr, ce que PowerShell transforme en erreur bloquante.
5. **L'argument `date` n'atteint pas le script de workflow** — d'où des dossiers `sans-date-*` et `a-dater-*`. À corriger en faisant lire la date par l'agent lui-même.

## Prêt à coder (analyses commitées)

- **Repères de section** (`docs/features/a-dater-reperes-de-section/`) — bandeau de marqueurs nommés. L'analyse a trouvé qu'il faut l'insérer *dans* le `ScrollViewer` de la règle : l'alignement horizontal devient gratuit.
- **Zoom horizontal** (`a-dater-zoom-timeline/`) — l'échelle est une constante unique traversée par 24 sites. Le nombre d'éléments dessinés ne dépend pas du zoom : un rendu à 400 % coûte le prix d'un rendu ordinaire.
- **Gestion des pistes** (`a-dater-gestion-des-pistes/`) — dupliquer, réordonner, et surtout **rendre la suppression annulable** : `Tracks.Remove` s'exécute aujourd'hui sans `PushUndo`, c'est la seule action irrattrapable de l'éditeur.

## Idées non traitées

Trois analyses indépendantes, parties de domaines différents, ont convergé sur les mêmes manques — signal plus fiable que le kanban :

1. **Vélocité par note** — citée par les quatre analyses, écartée par toutes pour la même raison (modèle + persistance + moteur + éditeurs). Ne sortira jamais d'un run à périmètre serré ; à traiter délibérément.
2. **Métronome et décompte à la lecture** — n'existe que dans l'enregistreur de riff.
3. **Swing dans l'aperçu de riff** — la timeline swingue, l'aperçu d'un riff isolé reste droit.
4. **Levée dans les trois exports de partition** — écrite comme une mesure complète ; à corriger d'un coup.
5. **Liaisons par-dessus la barre dans l'export `.mscx`** — même correction que celle livrée ici, sur un export en service.
6. **Sauvegarde automatique** — un plantage perd le travail non enregistré.
